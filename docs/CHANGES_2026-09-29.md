# edh-tool: changes from the 2026-09-29 session

Handoff notes for another agent. Repo root is `edh-tool/` (npm workspace: `engine` + `web`, plus a Python 3.10 `pipeline/`). Originals of files that were rewritten are in `_backup_2026-09-29/`.

## 1. Goal

edh-tool.com (Next.js on Vercel) recommends "hidden gem" Magic: The Gathering cards for Commander using AI-generated card tags and per-commander themes. This session added:

- decklist import
- a deck builder
- export to Archidekt, Moxfield and clipboard
- "which commanders fit this card?" search
- bulk theme generation for every black, green and colorless commander (the only colors tagged so far)

Decks live only in the browser (`localStorage`). No login, no server-side storage.

## 2. Product decisions (from the owner)

- The commander is chosen **after** import, or from suggestions computed from the cards.
- Searching a non-commander card shows commanders that fit it (Drown in Ichor -> Agent Frank Horrigan).
- The deck's **inferred theme drives recommendations**. The user can change or pin the theme at any time (`auto` or `pinned`).
- Two add actions: **Add to deck** and **Add to maybeboard**.
- Printings are preserved on import and export as raw `(SET) 123` strings; card data itself is per oracle card.
- Themes are generated for all commanders up front, not lazily, with no fallback path.
- Partner and background pairs are **deferred** (post-MVP).

## 3. Architecture

- **Shared pool.** One `web/data/pool.json` of tagged cards. Color-identity legality is filtered per commander at runtime. This replaces the old per-commander bundles (`web/data/commanders/<slug>.json`).
- **Scoring:** `fit^a x commanderMult x quality^b x popularityMult x artMult`, implemented in `engine/score.mjs` and shared by the pipeline, the site and the tests.
- **Themes:** 1-4 base vocabulary tags each, `kind` = `core` | `stretch`, `status` = `ok` | `rejected_unviable` | `partial` | `thin` | `needs_regeneration`. A theme is viable at >= 40 fitting cards (`themes.viability_min_cards`).
- **Deck storage:** `useSyncExternalStore` store with `schemaVersion`, a `migrate()` function and cross-tab sync via the `storage` event. Decks hold oracle ids, quantities and boards only. Card display data comes from `/api/cards`.
- **Deck theme state:** `{ mode: "auto" | "pinned", pinned: string[] }`.

## 4. Pipeline / engine changes

| File | Change |
|---|---|
| `pipeline/themes.py` | Rewritten. `build` skips commanders already in the output unless `--all`; computes per-color-identity supply once. `submit` / `status <id>` / `collect <id>` drive the Anthropic Message Batches API (`claude-sonnet-5-5`, `themes.max_tokens` 16000). `collect` saves raw answers to `data/batch/theme_results.<id>.jsonl`, then ingests. `ingest` accepts one model-output JSON or the saved `.jsonl`; validates, computes viability, merges by `oracle_id` into `data/commander_themes.jsonl`. `--quiet` prints only the summary. Requests use `custom_id = themes-<oracle_id>`. |
| `pipeline/themes.py` `check_motifs` | **Performance fix.** It recomputed the legal-card list for every commander and ran a regex over every card's labels for every motif, taking hours. Now caches legal cards per color identity and matches each motif against the distinct labels once. Same results; full ingest of 791 commanders takes about 2.5 minutes. |
| `pipeline/export_web.py` | Rewritten. Writes `web/data/pool.json`, `cards.json` (with `any_number` flag), `commanders.json`, `vocab.json`. Warns that `web/data/commanders/` is obsolete. |
| `engine/cli.mjs` | Added `viability-many --cards C --tags T --input IN.json` (one Node process for many commanders) plus `getCommander()` / `viaOpts()` helpers. |
| `engine/deck.mjs` (new) | `DECK_CONFIG`, `deckThemeProfile`, `activeThemeIds`, `deckRecommendations`, `suggestCommanders`. Types in `deck.d.ts`, with extras appended to `score.d.ts`. |
| `engine/decklist.mjs` (new) | `parseLine`, `parseDecklist`, `normalizeName`, `buildNameIndex`, `lookupName`, `suggestNames`, `resolveEntries`, `exportDecklist`. Types in `decklist.d.ts`. Export formats: `text`, `moxfield`, `archidekt` (Archidekt uses `[Category]` tags, `Commander{top}`, `Maybeboard{noDeck}{noPrice}`). |
| `engine/package.json` | Exports `.`, `./deck`, `./decklist`. |
| `tests/deck.test.mjs`, `tests/decklist.test.mjs` (new) | Root `test:engine` is now `node --test tests/*.test.mjs`. |
